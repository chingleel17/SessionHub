# agents-resource-cache Specification

## Purpose
定義 Agents 頁面中 Skills、Commands、MCP 清單的首次偵測、程序期間快取及手動重新整理契約，讓使用者再次進入已載入的頁籤時立即看到資料，減少重複磁碟存取，並在明確修改後維持專案與全域資料一致。

## Requirements

### Requirement: 資源首次偵測後使用程序期間快取

系統 SHALL 對專案與全域的 Skills、Commands、MCP 分別在首次開啟且資料來源已確定時偵測一次，並將成功結果保留於本次應用程式程序的記憶體。空清單 SHALL 視為有效結果。相同資源上下文命中快取時 SHALL 立即呈現資料，不等待磁碟掃描或 CLI discovery；頁籤未曾開啟時 SHALL NOT 預先偵測其資源。專案頁中的全域分區 SHALL 與全域 Agents 頁共用同一份快取。

#### Scenario: 首次開啟只偵測一次
- **WHEN** 使用者首次開啟某專案 Skills 頁籤且設定已載入
- **THEN** 該專案技能清單只偵測一次，不因初始變更簽章或暫時空設定再偵測第二次
- **AND** 專案頁所需的全域 Skills 在無快取時各自偵測一次，其他資源頁籤不載入

#### Scenario: 切回已有快取的頁籤
- **WHEN** 使用者載入專案 Commands 後切到其他頁籤再切回
- **THEN** 立即呈現原快取，不重新偵測檔案或呼叫 CLI discovery

#### Scenario: 空清單保持快取
- **WHEN** 某資源首次偵測成功但沒有項目，使用者離開再返回
- **THEN** 顯示原空清單，不因項目數為零再次偵測

#### Scenario: 跨畫面共用全域資料
- **WHEN** 使用者已於專案頁載入全域 MCP，接著開啟全域 Agents 頁的 MCP
- **THEN** 使用相同快取，不重新讀取全域 MCP 設定

#### Scenario: 重新啟動
- **WHEN** 應用程式結束後重新啟動並首次開啟資源頁籤
- **THEN** 該資源重新偵測一次，先前清單快取不由額外磁碟副本還原

### Requirement: 已載入資源不做背景重驗證

系統 SHALL NOT 因計時輪詢、資料經過一定時間、頁面重新掛載、視窗焦點切換、網路恢復或外部檔案通知，重新掃描已載入的 Skills、Commands、MCP。這些畫面的相依顯示偵測（Skills 連結狀態、專案偏好、Codex MCP 專案信任狀態）SHALL 採相同策略。外部修改 SHALL 於使用者手動重新整理後才反映；工具內成功寫入後的更新依本規格之操作後更新需求處理。

#### Scenario: 閒置與焦點切換不掃描
- **WHEN** 使用者載入 Skills、Commands、MCP 後停留超過原查詢到期時間，並切出視窗再切回或恢復網路
- **THEN** 這些資源及相依顯示偵測不新增背景磁碟讀取或 CLI discovery

#### Scenario: 外部變更等待手動更新
- **WHEN** 使用者在外部新增技能、修改 command 或 MCP 設定，尚未按重新整理
- **THEN** 頁面維持已載入的清單，不主動偵測變更

### Requirement: 快取依資料來源隔離

系統 SHALL 依資源種類、scope、專案路徑、已啟用 provider 集合及影響資料的來源設定隔離快取。專案技能忽略設定 SHALL 納入技能資料上下文。無關的顯示設定變更 SHALL NOT 觸發偵測。切換到尚無快取的來源 SHALL 顯示載入狀態，不以另一專案或另一來源的上一份清單替代。

#### Scenario: 不同專案不得共用清單
- **WHEN** 使用者從已載入的專案 A 切到尚未載入的專案 B
- **THEN** B 首次偵測一次，期間不顯示 A 的資源清單；返回 A 時直接使用 A 的快取

#### Scenario: 來源路徑改變
- **WHEN** 使用者將全域技能來源改為另一個目錄並開啟 Skills
- **THEN** 新來源首次偵測一次，不使用舊來源快取

#### Scenario: 失敗上下文不阻擋新來源
- **WHEN** 某來源首次偵測失敗，使用者改成另一個資料來源
- **THEN** 新來源仍可首次偵測一次，舊來源的失敗狀態不阻擋新來源

#### Scenario: provider 順序與顯示設定不影響來源
- **WHEN** 已啟用的 provider 集合不變但排序改變，或使用者只調整主題
- **THEN** 使用原快取，不重新偵測

### Requirement: 重新整理只更新指定資源且保留最後成功結果

既有重新整理按鈕 SHALL 偵測按鈕所屬 scope、當前資源頁籤及其相依顯示資料，不掃描其他 scope 或資源頁籤。同一上下文的載入或重新整理在執行中 SHALL 合併重複請求，不取消並重啟掃描。更新時 SHALL 保留上次成功資料；成功後替換快取，失敗時保留舊資料、呈現錯誤且不自動重試。無成功資料的初次失敗 SHALL 保留錯誤狀態，使用者重新整理才再試。

#### Scenario: Skills 重新整理範圍
- **WHEN** 使用者點擊專案 Skills 分區的重新整理
- **THEN** 重新偵測專案 Skills 與必要相依資料，未變更資料來源時技能偵測只執行一次
- **AND** 全域 Skills、Commands、MCP 及 AGENTS.md 清單不重新掃描

#### Scenario: MCP 重新整理包含信任狀態
- **WHEN** 使用者點擊專案 MCP 分區的重新整理
- **THEN** 更新該專案 MCP 清單及 Codex 專案信任狀態，不重讀全域清單或 Skills／Commands

#### Scenario: 重複點擊合併
- **WHEN** 同一資源已在首次載入或手動重新整理中，使用者再要求重新整理
- **THEN** 維持同一筆執行中的偵測，不產生並行或取消重啟的重複掃描

#### Scenario: 重新整理失敗
- **WHEN** 已有成功清單，重新整理因檔案權限或 CLI 錯誤失敗
- **THEN** 保留最後成功清單並呈現錯誤，使用者可再按重新整理，不自動再次偵測

#### Scenario: 首次偵測失敗後切換頁籤
- **WHEN** 某資源首次偵測失敗，使用者切離頁籤再返回
- **THEN** 維持錯誤狀態，不隱式重試；按重新整理才再偵測

### Requirement: 明確寫入後更新受影響快取

使用者在工具內成功執行 MCP 新增、編輯、啟停、刪除、複製，Skills／Commands 實際同步，或全域技能連結建立後，系統 SHALL 更新受影響的已載入資料。可見資料 SHALL 明確重新偵測一次；已載入但不可見資料 SHALL 標記待更新並在下次開啟時偵測一次；尚未載入資料 SHALL NOT 因寫入而預熱。相同全域資料的所有畫面 SHALL 一致。同步預覽、全部略過、寫入失敗與 MCP 測試連線 SHALL NOT 觸發資源重掃。

#### Scenario: MCP 編輯後一致
- **WHEN** 使用者在專案頁全域 MCP 分區成功編輯 server
- **THEN** 更新全域 MCP 快取，專案頁全域分區與全域 Agents 頁一致，專案 MCP 不重掃

#### Scenario: 同步只更新受影響種類
- **WHEN** 使用者成功同步專案技能且至少有一項實際寫入
- **THEN** 更新受影響的 Skills 快取，不掃描無關 Commands 或 MCP

#### Scenario: 預覽不刷新
- **WHEN** 使用者只預覽技能同步或測試 MCP HTTP 連線
- **THEN** 清單快取不失效，不重新掃描資源

#### Scenario: 寫入期間切換專案
- **WHEN** 專案 A 的寫入尚未完成時，使用者切換到專案 B
- **THEN** 寫入完成僅更新 A 的受影響快取，不將 A 的結果套用到 B

#### Scenario: 寫入與先前掃描競爭
- **WHEN** 一筆寫入在同上下文的先前掃描期間成功
- **THEN** 最終快取反映寫入後狀態，不以先前掃描的舊結果覆蓋新資料

### Requirement: 分層掃描共用資源上下文

同一專案資源的 root 與 nested SHALL 視為一次依序執行的邏輯偵測，使用既有完整來源上下文快取。根層結果 SHALL 在背景階段完成前可見，重新整理期間 SHALL 保留已載入的子目錄資料；背景失敗 SHALL 保留可用資料與未完成標示。寫入後更新、重複刷新合併與手動重試 SHALL 遵守既有規則。

#### Scenario: 刷新期間保留資料
- **WHEN** 使用者重新整理已完整載入的 Skills
- **THEN** 根層與子目錄依序重新掃描，期間保留原子目錄清單
- **AND** 成功時以完整新結果替換，刪除已不存在的項目

#### Scenario: 不同專案與取消
- **WHEN** 專案 A 正在掃描時切換到專案 B，或先前請求已取消
- **THEN** A 的中間與最終回應不更新 B，已取消回應不覆蓋同上下文的新資料

#### Scenario: 寫入發生於背景補齊期間
- **WHEN** 同一上下文的背景掃描尚未結束，技能同步成功寫入
- **THEN** 寫入後更新等待舊掃描結束再重新偵測，最終結果反映寫入後內容

### Requirement: 專案掃描優先於附帶全域掃描

專案 Agents 的 AGENTS.md 與 Skills 頁籤 SHALL 優先完成對應專案掃描，再於背景啟動尚未載入的全域資料；專案失敗 SHALL NOT 永久阻擋全域資料。獨立全域 Agents 頁 SHALL 直接載入，且與專案附帶全域分區共用快取。

#### Scenario: 專案初次開啟
- **WHEN** 首次進入專案的 AGENTS.md 或 Skills 頁籤
- **THEN** 先載入專案 root 與 nested，結束後載入全域資料
- **AND** 全域尚未啟動時不顯示成確定的空清單

#### Scenario: 直接進入全域頁
- **WHEN** 使用者在專案掃描期間切至全域 Agents
- **THEN** 全域頁可直接開始所選資源的載入，不等待先前專案
