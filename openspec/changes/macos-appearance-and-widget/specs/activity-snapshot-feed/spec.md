# Spec Delta

## Purpose

提供與任何視窗無關的活動快照（各平台用量與 session 狀態），使 overlay、tray panel 與原生 widget 等顯示面使用同一份資料與同一套狀態判斷。

## ADDED Requirements

### Requirement: 單一活動快照資料來源

系統 SHALL 以單一函式產生活動快照，內容包含各平台的 quota 快照、等待處理的 session 清單與處理中的 session 數量；所有顯示面 MUST 使用同一份結果，不得各自重新推導狀態。

#### Scenario: 快照內容

- **WHEN** 任一顯示面要求活動快照
- **THEN** 結果包含已啟用且未被過濾平台的 quota 快照、等待處理清單（含專案名稱）與處理中數量
- **AND** 狀態判斷採用既有的合併規則（herdr 偵測優先，hook 事件為退路）

#### Scenario: 過濾未啟用的平台

- **WHEN** 某平台的目錄不存在或未列於用量監控平台
- **THEN** 該平台不出現在快照內

### Requirement: 快照可供 App 外部的顯示面讀取

系統 SHALL 在活動狀態或 quota 變動時，將最新快照寫入一個 App 外部可讀取的共用位置，並標註產生時間，使不在 App 程序內的顯示面（例如原生 widget）可讀取。

#### Scenario: 狀態變動時更新

- **WHEN** 等待處理清單、處理中數量或 quota 快照發生變動
- **THEN** 系統在合理的節流間隔內更新共用快照，且寫入為原子操作，讀取端不會讀到半份資料

#### Scenario: 讀取端判斷過期

- **WHEN** 快照的產生時間距今超過約定的有效期限（例如 App 已結束）
- **THEN** 讀取端以「資料過期」呈現（灰燈與提示），而非顯示舊的紅燈或黃燈

#### Scenario: 快照不含敏感內容

- **WHEN** 系統寫入共用快照
- **THEN** 內容不包含憑證、token、完整檔案路徑或指令內容，僅含平台名稱、用量比例、重置時間、專案名稱與狀態
